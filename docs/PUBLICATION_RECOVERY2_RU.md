# Публикация проверенной recovery2 в main

Дата: 19 ноября 2026 года. Продукт: NOX 2026-11-18d.

## Что публикуется

Публичный идентификатор комплекта — `2026-11-19-recovery2-public1`.
Основа GitHub — только `main`, коммит `da86923760db9e90292de175d5fc5ddffe7e2129`.
Другие ветки не являются источником изменений и не обновляются.

Исполняемая логика соответствует доставленной и уже запущенной на Windows
сборке `2026-11-19-recovery2`. В модуле `nox_studio_18d.py` изменена только
константа `BUILD`. В сборщике и проверяющей утилите изменены идентификаторы
публичного комплекта, имя ZIP и заголовок протокола. В реестр совместимости
добавлен точный проверенный хеш модуля из recovery2. Неизвестный локальный
код автоматически совместимым не объявляется.

Сквозной тест обновления дополнительно сверяет все 33 файла исходного main
по Git-хешам из `tests/main_baseline.json`. Наличие допустимого хеша более
поздней recovery2 больше не принимается тестом за доказательство, что новый
модуль уже существовал в старом main. Это изменение проверочного стенда,
не алгоритма установки или обработки книги.

В `docs/PACKAGE_UPGRADE_RU.txt` два абсолютных пути рабочей среды заменены
обозначениями исходного main и кандидата ZIP. Результаты проверки и хеш
кандидата не меняются. README и CHANGELOG поясняют публичную сборку.
Манифест заново связывает точные байты этой публичной копии.

Отдельный build_id обязателен: установленный комплект неизменяем,
и другой манифест под прежним именем был бы отвергнут установщиком.
Переустановка уже работающей recovery2 для этой публикации не нужна.

Исходный доставленный ZIP `NOX_18d_recovery2_2026-11-19.zip` сохранён без
изменений. SHA-256:
`7688542b3636963db81df23b81d814206fcbccf6ba1da26bfef05f524ca4ba32`.

## Границы подтверждения

`docs/TEST_RESULTS_RU.txt`, `docs/ACTUAL_STATE_ACCEPTANCE_RU.txt` и
`docs/PACKAGE_UPGRADE_RU.txt` сохраняют исторические результаты recovery2.
Они не переименованы в результаты нового комплекта. Проверка публичной
копии записывается отдельно в `docs/PUBLICATION_CHECKS_RU.txt`.

Пользователь подтвердил выполнение штатных `-Check`, установки, запуска
18d и самопроверки без ошибок на целевом Windows. Это подтверждает этот
путь установки и запуск. Оно не заменяет прослушивание всех записей,
проверку всех действий интерфейса и перенос произвольной новой редакции.

Матрица функциональных требований и оставшиеся ограничения находятся в
`docs/REQUIREMENTS_18D_RU.md`. Наличие кнопки поиска старых озвучек не означает
автоматического монтажа любых прежних WAV в новую разбивку. Второго
параллельного таймлайна не реализовано. Сканирование звуковых подсказок не
является готовой художественной партитурой всех новых сцен.

При изменении рукописи защищённый префикс сохраняется только при однозначном
соответствии исходных абзацев. Изменённый текст внутри него блокирует
автоматическую подготовку. Для полной новой редакции требуется отдельный
проект и явная сверка переноса текста, голосов, дублей и звуковых отметок.
Рабочую книгу не следует использовать как пробный полигон перенарезки.

## Состав публикации

Публикуются исходники, синтетические тесты, общие справочные данные и
техническая документация из проверенного манифеста. Рабочие CSV/JSON книги,
рукопись, голоса, записи, архив переписки, диагностика ПК и внутренние
build_evidence в публикацию не включаются. Наличие файлов в рабочем
каталоге само по себе не добавляет их в публикуемый набор.
