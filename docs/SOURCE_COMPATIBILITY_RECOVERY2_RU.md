# Совместимость recovery2 с проверенной установкой

## Что проверено

В диагностическом снимке от 19 ноября 2026 года проверены все **49 назначений кода** из `preflight.json`: 25 существующих файлов и 24 отсутствующих новых компонента. SHA-256 каждого из 25 приложенных файлов совпал с записанным `old_hash`. Пропущенных существующих исходников или несовпадений хешей не обнаружено.

Сверка относится к исходникам и документам состояния, полученным в диагностике. Она не означает, что реальный Windows-компьютер уже обновлён. Рабочая озвучка и её аудиофайлы не входили в эту проверку.

## Какая версия была установлена

Это **смешанный комплект**, который нельзя точно назвать копией одного исторического ZIP:

| Группа | Результат сверки |
|---|---|
| 21 исходный файл | Побайтно совпадает с проверенной активной `main`: prep/go/run, launcher, обычные модули книги, проверка речи, HTML Studio, cues/import и инструменты очистки/публикации. |
| Runtime книги `nox_audiobook.py` | Совпадает с воспроизведённым `main + prep` после нормализации BOM и CRLF. Дополнительных местных функций в нём нет. |
| Общий `nox_audiobook.py` | Более ранняя базовая версия; установленные исправления добавляются патчем prep при создании runtime книги. |
| Общий `nox_fast.py` | Ранний общий воркер, побайтно найденный в исходном архиве переписки. В папке самой книги установлен уже расширенный воркер из `main`. |
| Python-код Studio | `main` с одним локальным исправлением выбора Python для движка. Оно сохранено в recovery2. |

Надпись `2026-11-12a` внутри ряда файлов не доказывает отсутствие более поздних исправлений. Точную совместимость здесь устанавливают содержимое и хеши, а не одна текстовая метка версии. Отбракованная ветка GitHub для сверки не использовалась.

## Три дополнительно проверенных исходных варианта

В recovery2 разрешаются только точные проверенные хеши соответствующих файлов. Проверка неизвестного кода не отключается и не заменяется разрешением любой версии.

### Studio: правильное окружение движка

Локальное отличие находится только в `Studio._engine_spawn`: вместо Python, которым запущен интерфейс, выбирается `<книга>/envfast/Scripts/python.exe` с проверкой существования. Другие функции, классы и HTML совпадают с `main`.

В recovery2 для этого используется `self.tool_py('fast')`, где окружение книги является первым штатным кандидатом. Сохранены также явная настройка `NOX_TOOL_PY` и предусмотренный выбор общего envfast. Отдельная проверка действующего `_engine_spawn` запускает его с отличающимся Python интерфейса и проверяет путь дочернего процесса, редакторский воркер, лимит токенов и его окружение. Запуск самого процесса в этой проверке заменён контролируемым стендом; CUDA не использовалась.

Нормализованный SHA-256 проверенного предыдущего файла:

```text
app/nox_studio.py
2f75d70b6b7493bcdfb3fd454429d52f5b364d46fa2708d7f5b5b5b4c9040f70
```

### Общий base: ранняя версия, которую дополняет prep

По сравнению с базой из `main` в старом общем файле отсутствуют только известные улучшения `chunk_text`, относительная обрезка тишины с запасом окончания, `part_source_seconds` и необходимый импорт `math`. Уникальных местных функций не обнаружено.

Патч из **фактически установленного prep** применён к временной копии **фактически установленного общего base**. Полученный код после нормализации совпал с runtime установленной книги. Следовательно, ранний общий base не означает, что книга работала без этих исправлений.

Нормализованный SHA-256 для проверки совместимости отличается от исходного файлового хеша из-за BOM/переводов строк:

```text
home/nox_audiobook.py
2f8508ad7a822eea553e401132f76636479eba9070d121fd70f67abee960c7f0
```

### Общий fast: ранний воркер

Старый файл размером 8165 байт совпал с ранним исходником из архива. В нём ещё нет редакторской очереди, режима частей и более поздних проверок качества. Установленный воркер **самой книги** уже содержит эти функции и совпадает с `main`.

Recovery2 сохраняет прежние CLI-параметры общего воркера. Модель и обработка ударений по умолчанию соответствуют расширенному воркеру книги; это отличается от старой общей утилиты, по умолчанию использовавшей базовую модель без `acute`. Прежний файл входит в резервную копию кода для точного отката.

```text
home/nox_fast.py
ea467de689b7a3f5dfe0a0a85e012fe48f860bba42f0eae8a422cc2cb21bcaf1
```

## Проверка реального состояния и пределы приёмки

На исходных документах диагностики новая проверка подтверждает 18 541 строку CSV, 73 открытые и закреплённые части, 42 авторские вставки и одну выбранную запись внутри закреплённой части без отдельного снимка `locked`. Такая запись сохраняется как фактический выбранный дубль; фиктивное индивидуальное закрепление для обхода проверки не создаётся.

Для проверки файловых операций используется отдельная временная копия документов. Поскольку настоящих записей в диагностике нет, требуемые WAV и JSON создаются **явно синтетически** по существующим ссылкам на дубли. Это позволяет проверить связь состояния с файлами, отказ при отсутствующем WAV или несовпадающем JSON, установку кода и его откат. Такая проверка не подтверждает наличие, целостность или звучание настоящих аудиофайлов. Окончательный результат установки и отката указан в протоколе конкретного собранного архива.

Исходные документы не исправляются в ходе приёмки; их хеши сверяются до и после. Служебный проверочный скрипт и реальные документы диагностики находятся вне состава публичного релиза.

Отдельный путь базового Python, показанный Windows CIM, сам по себе не означает неправильное окружение: venv может использовать redirector. Это поведение описано в [документации Python 3.12 — venv](https://docs.python.org/3.12/library/venv.html). Для диагностики окружения нужны фактические `sys.executable`, `sys.prefix`, `sys.base_prefix` и результат импортов. Сверка кода не подменяет эту проверку на целевом ПК.
