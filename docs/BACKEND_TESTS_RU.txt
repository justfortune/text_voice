NOX 2026-11-18d — проверка восстановленной интеграции backend
Сборка: recovery2, 2026-11-19

Это результаты новых проверок интегрированного кода. Они не воспроизводят
заявленные в прежней переписке 121/128 тестов и не удостоверяют побайтное
тождество отсутствующему историческому ZIP 18d.

Выполненные команды из корня комплекта:

  python -B -m unittest discover -s tests -p 'backend_*.py' -q
  Ran 66 tests — OK

  python -B -m unittest discover -s tests -p 'publishing_*.py' -q
  Ran 12 tests — OK

  python -B -m unittest discover -s tests -p 'protection_*.py' -q
  Ran 65 tests — OK

В backend входят 58 проверок recovery1 и восемь адресных проверок recovery2:
настоящий вызов запуска движка через envfast книги; загрузка выбранной записи
в закреплённой части без отдельного снимка фразы; сохранение этой записи при
clean_takes; доступность ручного set_seg/choose_take; отказ от автоматической
замены «пустого» выбранного дубля; отказ от неоднозначной перепривязки его UID;
сохранение этой защиты после save для вставки за последней исходной фразой части;
сохранение ссылок голосов из метаданных такого выбора при уборке образцов.
Подробности механизма защиты конвейера и его собственных 65 проверок приведены
в tests/PROTECTION_RECOVERY2_RESULTS.txt и общем docs/TEST_RESULTS_RU.txt.
Числа относятся к разным наборам тестов.

Что проверено фактически

1. Studio: используются методы настоящего класса и действующие HTTP-маршруты,
   а не только модели алгоритмов. JSON и небольшие WAV создаются в отдельных
   временных книгах. Проверены удаление дубля и Undo, сброс правок с дублями,
   повторное открытие после сбоя, фиксация edits.json вместе с fixed_parts.json,
   разблокировка фраз внутри закреплённой части, конфликт внешней записи.

2. WAV и присутствующие JSON сопровождаются журналом с SHA-256. Проверены
   сбой между перемещениями и документами, откат комплекта, повторное
   восстановление, отказ при неизвестной версии файла. При ошибке rename
   исходные файлы не удаляются. Перемещения выполняются внутри соответствующего
   тома; существующий целевой файл не заменяется.

3. clean_takes сохраняет оба режима. В обоих дубли отправляются в транзакционную
   корзину с возможностью Undo; backup=True дополнительно сохраняет .noxproj.
   Это снимок состояния проекта, не полная дополнительная копия всех аудиофайлов.
   Проверены ссылки из закреплений, Undo и сохранённых проектов; восстановление
   проекта из новой корзины; конфликт номера дубля со старым карантином.
   Перенос в корзину не объявляется освобождением места на диске.

4. Для обрезки проверены явные retained spans: один и несколько оставленных
   диапазонов, обработка в сборке и склейке; пустой результат отвергается до
   изменений. Следующая фраза начинается после последнего сохранённого диапазона.
   Проверены защищённые фразы и авторизация соответствующих HTTP-запросов.

5. Старые записи: проверено происхождение Studio-дублей и прежних WAV конвейера.
   В тестах используется настоящий archive_stem, проверяемый снимок CSV/roles,
   каталог, предпросмотр и принятие кандидата. Неоднозначный текст, несколько
   положений одного WAV, неизвестное происхождение и повреждённые SHA/UID
   не допускают автоматического выбора. Текст цели не выдаётся за исходный текст.
   Автовыбор требует уникального совпадения исходного текста, роли и технического
   текста с нынешними правками; ручной выбор сохраняет исходные сведения.

6. Проверены изменение вложенной метаинформации, исчезновение WAV, ограниченный
   обход звукового каталога, обновление кэша, страницы выдачи, выбор canonical kit
   из записи установленной сборки и корректного Python. Неподтверждённая
   перепривязка повторяющихся фраз не заменяет прежнюю редакцию догадкой.

7. Во время запуска конвейера не создаётся дополнительный редакторский воркер
   без необходимости. Явный force сохраняет возможность отдельного запуска.
   Значение 1500 представлено как max_new_tokens; это не размер batch.
   Проверка readiness согласована с heartbeat только после успешного прогрева.

   Recovery2 дополнительно проверяет именно _engine_spawn/Popen: исполняемый
   файл берётся из envfast/Scripts/python.exe этой книги при отличающемся Python
   самой Studio. Сохранён смысл локального исправления установленной версии;
   не меняются среда и установленные пакеты. Явный NOX_TOOL_PY остаётся отдельной
   настройкой, а не результатом подстановки интерпретатора интерфейса.

   У выбранной записи внутри закреплённой части может отсутствовать отдельный
   locked-снимок фразы. Recovery2 не добавляет ему придуманные исторические
   значения и не запрещает обычные ручные правки/выбор дубля. Защита части от
   конвейера и выбранный WAV/JSON сохраняются. Автоматическая проверка тишины
   сообщает о сомнительной записи, сохраняя выбор; неоднозначная перепривязка
   её UID останавливается. Пересчёт этого индекса после save читает метаданные
   в памяти, не перечитывая всё аудио книги. Принадлежность авторских вставок
   определяется теми же правилами привязки, что в nox_freeze, в том числе если
   вставка идёт после последнего исходного UID закреплённой части.

8. Порядок в образцах голосов: проверяется настоящий cmd_tidy и сгенерированный
   runtime книги. Без --apply обход остаётся только отчётом. С применением целые
   WAV/TXT и присутствующие JSON перемещаются в уникальные каталоги с журналом
   SHA-256; прежние roles.json и bank.json сохранены. Существующий карантин и
   одинаковые имена из повторных запусков не перезаписываются.

   Изолированно воспроизведены: ошибка второго перемещения; прерывание после
   первого файла; отказ восстановления при живом процессе; неизвестный SHA
   перед восстановлением; отказ bank.json после изменения roles.json;
   повреждённый банк или история; ссылки закреплённой редакции и проверенных
   прежних снимков. Во всех штатно восстанавливаемых сценариях исходные
   файлы и метаданные возвращены вместе. Неподтверждённые состояния оставляют
   marker и журнал для разбирательства, без перезаписи неизвестного файла.

   Явное восстановление после прекращения процесса:
     python nox_voice_safety.py --root ПАПКА_КНИГИ --recover
   Для tidy этот вход передаёт управление nox_voice_tidy.recover_tidy.
   Подготовка и другие записи Studio блокируются незавершённой операцией.

9. Публикация кода: 12 проверок используют настоящие Git-репозитории и локальные
   bare remotes во временных каталогах. Проверены отсутствие изменений при
   предварительном просмотре, локальный commit с -NoPush, отдельный явный -Push,
   сохранение посторонней ветки, отказ при грязном рабочем дереве, неизвестных
   коммитах/файлах, изменении remote main, другой активной ветке, повреждении
   manifest и сбое копирования. Проверены запрет частных данных в payload и
   истории новых коммитов, строгий список кода, режим -NoZip без диагностического
   архива. Никакой реальный GitHub или рабочий репозиторий пользователя не менялся.

   v_github.ps1 не выполняет force push, reset, переименование ветки или скрытое
   изменение origin. sborshchik_k1a.ps1 по умолчанию проверяет состояние; -Fix
   использует полный комплект и штатный обновлятор. Скрипты не собирают версию
   из отдельных файлов Downloads и не удаляют посторонние скрипты.

Практические границы проверки

- Все перечисленные тесты выполнены на изолированных Linux fixtures.
  GPU-модель, CUDA, реальные длительные аудиокниги и звуковое качество не
  проверялись этими тестами. Для малых аудиофикстур используется stdlib wave
  и тестовый адаптер чтения, а не установленный звуковой стек пользователя.
- PowerShell проверен по исходникам на совместимость с 5.1 и опасные команды;
  реальный запуск в Windows и поведение открытого Яндекс Диска здесь не проверены.
  Обновлятор дополнительно выполняет доступные проверки перед заменой кода.
- Принудительное прекращение моделировалось исключением, обходящим обычный
  откат, с оставленным журналом. Это проверяет логику восстановления, но не
  является испытанием физического сбоя диска или выключения питания.
- Поддерживается исключение одновременных записей данной книги через общий
  operations.lock. Сторонние программы, не соблюдающие этот протокол, могут
  вызвать контролируемый конфликт SHA; неизвестные изменения не исправляются
  автоматически. Глобальный банк не следует менять другой программой во время
  его обслуживания.
- Файлы пользователя не устанавливались и не менялись. Успех тестов не заменяет
  проверку совместимости именно установленного экземпляра и его данных.
