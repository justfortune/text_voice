Основа кода: `justfortune/text_voice`, только `main`, коммит `da86923760db9e90292de175d5fc5ddffe7e2129`. Назначение изменений восстановлено по переданному архиву переписки, включая поздние патчи 18c/18d. Это новая проверяемая сборка с отдельным идентификатором; она не выдаётся за побайтную копию исторического ZIP 18d, которого в переносе нет.

Главная точка входа для существующей 12b — **`Update_NOX_18d.ps1`**. Не накладывайте отдельные файлы вручную и не запускайте установку окружения с нуля для обновления работающей книги.

## Публичная исходная сборка

`recovery2-public1` публикует проверенный код `recovery2`. Отдельный идентификатор нужен потому, что из тестового отчёта убраны внутренние пути среды, обновлены инструкции и манифест. В исполняемом коде Studio меняется только идентификатор сборки; алгоритмы и данные книги не меняются.

**Если `recovery2` уже установлена и работает, переустановка ради публикации не нужна.** Исходный доставленный ZIP `NOX_18d_recovery2_2026-11-19.zip` и его неизменяемый комплект не заменяются. Его SHA-256: `7688542b3636963db81df23b81d814206fcbccf6ba1da26bfef05f524ca4ba32`. Подробности состава и проверки публичной копии — в `docs/PUBLICATION_RECOVERY2_RU.md`.

## Что исправлено после первой проверки

Предыдущая сборка `recovery1` остановилась на старом допустимом состоянии: часть отмечена закреплённой, но у одной входящей фразы снято индивидуальное закрепление и выбран сохранённый дубль. В `recovery2` учитываются оба уровня защиты. Весь диапазон части защищён от автоматического конвейера; выбранный WAV и его JSON проверяются и сохраняются отдельно. Индивидуальный `locked` не добавляется, выбор дубля не меняется, флаг части не снимается при обновлении.

Это адресная совместимость: фраза должна иметь явные `sid` и `take`, соответствующий WAV и читаемые метаданные именно этого дубля. Неизвестный выбор, повреждённые документы, несовпадающие границы и неподтверждённые склейки по-прежнему останавливают проверку. Подробная сверка фактически установленного кода — в `docs/SOURCE_COMPATIBILITY_RECOVERY2_RU.md`.

Проверка тишины сообщает о сомнительной выбранной записи такой части и оставляет выбор автору. Автоматическая перепривязка не переносит её UID на другую фразу. Эта защита сохраняется после записи правок, в том числе для вставки сразу после последней исходной фразы части; ручной выбор другого дубля остаётся доступным.

Также сохранена локальная правка запуска редакторского движка через `envfast` книги. Разрешены три дополнительно изученных исходных хеша; защита от замены неизвестного кода остаётся включённой. Если одновременно найдены несовместимый код и ошибка состояния, новая проверка сообщает обе причины.

## Обновление текущей книги

Дождитесь завершения текущей сборки/озвучки, штатно остановите автоматический режим и движки, закройте все окна Studio этой книги. **Пауза и закрытие окна — разные действия:** открытая Studio продолжает обслуживать проект. Дайте ей и редакторскому воркеру время завершиться. Установщик сначала проверит процессы книги и общего редактора; принудительно завершать их он не будет. Если процесс ещё работает, проверка покажет его PID и завершится до чтения изменяемого состояния книги.

Распакуйте весь ZIP в отдельную папку. Например, из обычного PowerShell:

```powershell
$bundle = Join-Path $env:USERPROFILE 'Downloads\NOX_18d_recovery2_public1_2026-11-19'
Expand-Archive -LiteralPath (Join-Path $env:USERPROFILE 'Downloads\NOX_18d_recovery2_public1_2026-11-19.zip') -DestinationPath $bundle
powershell.exe -NoProfile -ExecutionPolicy Bypass -File (Join-Path $bundle 'Update_NOX_18d.ps1') -Root 'D:\kniga1a' -NoxHome 'D:\nox_audiobook' -Check
```

`-Check` не заменяет файлы установки. Проверяются целостность всего комплекта, синтаксис PowerShell средствами вашего интерпретатора, известные контрольные суммы старого кода, согласованность закреплений, наличие WAV/JSON закреплённых и явно выбранных внутри закреплённой части дублей, отсутствие незавершённых операций. Состояние книги сверяется до и после проверки, чтобы не принять изменившийся снимок. Чтение закреплённых записей не означает копирование всего аудио.

Для этой сборки используйте новую папку `NOX_18d_recovery2_public1_2026-11-19`, а не распакованный ранее `NOX_18d_rebuilt_2026-11-19`. Если новое имя уже занято вашей прежней распаковкой, задайте другую пустую папку в `$bundle`; смешивать файлы комплектов не требуется.

**Если проверка завершилась успешно**, примените тот же комплект:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File (Join-Path $bundle 'Update_NOX_18d.ps1') -Root 'D:\kniga1a' -NoxHome 'D:\nox_audiobook'
```

Затем откройте прежний ярлык Studio. Для явного запуска проверенного комплекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'D:\kniga1a\nox_studio.ps1' -Root 'D:\kniga1a' -NoxHome 'D:\nox_audiobook'
```

При первом запуске проверьте номер версии, откройте прежнюю закреплённую часть и прослушайте несколько мест с правками и звуками. Переозвучку новой фразы и экспорт проверьте в незакреплённой части. Это короткая приёмка на вашем Windows/RTX 3090; изолированные проверки исходников не подменяют её.

### Если обнаружена неизвестная локальная сборка

Надписи `12a`/`12b` в старых файлах не позволяют однозначно узнать их содержимое. Установщик принимает только известные исходные хеши или уже установленные байты этого комплекта. При отличиях он остановится **до замены кода** и создаст в Downloads файл `NOX_18d_preflight_<дата-время>.zip`.

Пришлите этот диагностический ZIP. В нём исходники и небольшие файлы состояния книги; нет WAV, моделей и окружений. CSV и JSON могут содержать текст книги, поэтому это материал для продолжения работы здесь, а не для публичного GitHub. Повторно присылать большой архив Claude для такой сверки не нужно.

Отличающийся код не объявляется повреждённым: это может быть другая корректная итерация 12b. Не добавляйте его хеш вручную в список допуска — сначала нужно проверить различия.

Весь комплект проверяется по SHA-256. Он сохраняется в `D:\nox_audiobook\kits\2026-11-19-recovery2-public1`; код книги и общего редактора устанавливается из этого комплекта. Прежние заменяемые файлы и журнал операции сохраняются в `D:\nox_audiobook\update_backups\<дата-время>`. Две записи версии связывают книгу и общий редактор с конкретным полным комплектом.

Резервируется заменяемый код, а не десятки гигабайт озвучки.

Откат кода — с точным путём журнала, напечатанным установщиком:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File (Join-Path $bundle 'Update_NOX_18d.ps1') -Root 'D:\kniga1a' -NoxHome 'D:\nox_audiobook' -Rollback 'D:\nox_audiobook\update_backups\ИМЯ_ОПЕРАЦИИ\update.json'
```

Автоматический откат допускается, пока после обновления не изменилось состояние книги и никто не заменил код/резервные копии. Он не подставляет старые правки поверх новых. При таком конфликте сохранённый журнал позволяет разбирать восстановление адресно.

## Работа после обновления

### Закреплённая редакция и новая подготовка

Защита читает оба источника закреплений: `studio/edits.json` и `studio/fixed_parts.json`. Проверяются реальные UID и границы частей, отдельные закрепления, выбранные дубли старых частично разблокированных частей, склейки и вставки. Ошибка чтения или несовпадение не превращаются в пустой список защиты. При загрузке прежнее индивидуальное снятие закрепления не заменяется вымышленным снимком: ручные операции продолжают учитывать действительные флажки фраз.

При новой нарезке сохраняется подтверждённое начало книги до последней защищённой реплики, включая остаток её абзаца. Соответствие абзацев проверяется по содержимому и порядку, а не только по изменяемому номеру `para`. Если текст защищённого начала изменён либо перенос активных правок/звуков неоднозначен, подготовка останавливается с объяснением. Изменение такого фрагмента требует явного снятия закрепления и редакторского решения.

Перед публикацией новой рукописи/таблицы/ролей создаётся проверяемый снимок состояния. Новые внешние словари, сценарии и ударения имеют собственную историю входных файлов. Это отдельная версионность входов, а не обещание одной общей транзакции для всего запуска `go`.

`go` по умолчанию использует текущие `book.docx` и файлы в `work`. Новую рукопись задавайте в таблице настроек; новые входы можно передать явно:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'D:\kniga1a\go_kniga1a.ps1' -Root 'D:\kniga1a' -Dict 'D:\новые_данные\accent_dict.csv' -Overrides 'D:\новые_данные\speaker_overrides_kniga1a.tsv' -StressFixes 'D:\новые_данные\stress_fixes_kniga1a.tsv'
```

Обычный запуск без этих ключей сохраняет текущие входы. Сценарии ролей и новую рукопись из поздней переписки нельзя автоматически назначать уже озвученной другой редакции книги.

### Дубли, обрезка и отмена

Удаление/сброс дублей согласованно меняет WAV, JSON и состояние проекта. Ctrl+Z возвращает и файлы, и ссылки на них; есть восстановление прерванных операций. Обрезка передаёт явный список сохраняемых интервалов: один или несколько допустимых интервалов учитываются при обработке и экспорте, а пустой результат отклоняется до изменения файлов. Старые допустимые одиночные интервалы остаются совместимыми.

Обе кнопки очистки дублей сохранены. «С копией» создаёт дополнительную точку возврата проекта; «без копии» её не создаёт. В этой сборке обе операции используют восстанавливаемую корзину. **Это осознанное изменение прежнего поведения:** в старом коде второй режим физически удалял файлы.

### Возврат прежней озвучки

История охватывает осиротевшие дубли Studio и сохранённые записи конвейера. Используются снимки редакций, контрольные суммы WAV и записи о перемещении. Исходный текст старой записи не заменяется текстом новой фразы в её происхождении.

Можно прослушать старый вариант и выбрать его вручную. Автоматическое присоединение ограничено подтверждёнными однозначными соответствиями; похожесть текста сама по себе не служит разрешением. Запись неизвестного происхождения показывается как таковая.

История сохраняет то, что доступно на момент снимка/операции. Она не может восстановить WAV, который был окончательно удалён прежними версиями до установки этой сборки.

### Звуки, экспорт и Яндекс Диск

Каталог внешних звуков поддерживает разделы, подразделы, русские подписи, поиск, страницы результатов, прослушивание, вставку и явное обновление. Обход каталогов ограничен во время чтения, а не после полного сканирования.

Голос, варианты со звуком, сопроводительные файлы и отметка экспорта публикуются согласованно. Сбой кодирования или замены одного файла сохраняет прежнюю версию. Подпись звуков части зависит от её диапазона: изменение чужой части не должно делать её устаревшей.

Копирование аудио в локальную папку Яндекс Диска и сохранение `edits_backup.json` имеют раздельный результат. Если аудио скопировано, а Windows временно заблокировала JSON, путь копии сохраняется и выводится точное предупреждение. Наличие локальной копии не является подтверждением завершённой облачной синхронизации клиентом Яндекса.

### Статус и движки

`go -Status` и `nox_part --status/--report` читают состояние, не запускают подготовку и не перезаписывают закрепления. Воркеры повторно проверяют актуальное окно перед занятием задания и публикацией результата. Объявление готовности модели следует за успешным прогревом.

Во время подготовки `go` обычный запуск редакторского движка ожидает штатные воркеры книги. Параметр `max-new-tokens 1500` задаёт предел длины генерации; это не размер батча. Установка `flash-attn`/SoX не выполняется автоматически ради исчезновения предупреждения из журнала.

## Восстановление и обслуживание

Порядок работы инструментов очистки и возврата карантина описан в `docs/MAINTENANCE_18D_RU.md`. По умолчанию они показывают план. Очистка останавливается при закреплениях, открытых частях, несогласованных данных, активных процессах и незавершённом восстановлении. Перемещённое аудио остаётся в карантине на том же диске; это не освобождение занятого им места.

Уборка неиспользуемых образцов голосов отдельно проверяет банк, роли и подтверждённую историю голосов. WAV и присутствующие TXT/JSON перемещаются вместе; повреждённые метаданные останавливают операцию. Проверка существования процесса при восстановлении на Windows выполняется через API чтения состояния процесса и не отправляет ему сигнал завершения.

Не пытайтесь лечить проблему обновления очисткой книги. Для неизвестной версии нужен диагностический ZIP установщика, а для прерванной операции — её конкретный журнал.

## Проверки и границы приёмки

Точный протокол находится в `docs/TEST_RESULTS_RU.txt`, соответствие требованиям — в `docs/REQUIREMENTS_18D_RU.md`. Автотесты проверяют реальные функции/обработчики и взаимодействие файлов на временных проектах, в том числе отказы записи и восстановление.

Дополнительно использованы настоящие документы диагностического снимка: 18 541 строка CSV, 73 закреплённые части и 42 авторские вставки. Отдельная сквозная приёмка использует их временную копию и явно синтетические WAV/JSON по существующим ссылкам. Настоящие аудиофайлы в диагностике отсутствуют; их наличие проверит `-Check` на вашем компьютере. Частные документы, их копия и стенд приёмки не входят в ZIP или публикацию кода.

В этой среде нет вашего Windows PowerShell 5.1, RTX 3090, настоящих моделей и полной текущей папки книги. Генерация речи и полноценная работа графического окна на вашем ПК требуют описанной выше короткой приёмки. Запуск Chromium здесь был заблокирован средой до загрузки страницы; это не засчитано как пройденный браузерный тест.

Исторические заявления «128 тестов» и «21 тест» из прежних чатов не прибавляются к числу проверок этой сборки.
